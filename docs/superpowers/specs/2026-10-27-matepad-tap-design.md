# MatePad 单击和快速双击设计

日期：2026-10-27。用户审阅后回复“动手动手”，已确认按本方案实施及验证；具体实际进度见工作日志。

## 目标和当前证据

在已有同一份dual固件上增加MatePad系统蓝牙单击：触摸板轻点松手，平板屏幕中心产生一次点击；快速点两次，平板收到两次按顺序点击。继续支持上下滑翻页、OPPO App单击/上下滑，一次控制一台，日常切换不刷机。首点不等待双击判定，动作完成后不另加固定冷却。

2026-10-27用户已在当前`8dceb250509ae1ca605e6c0d27d3907f93a300f414d6a3bc3a48b4a7b189e2fa`版确认平板上下滑可以翻页，并反馈单点没有结果。现有平板实现仅HID键盘、短点只进入App路线，故平板无单点是现有功能边界，并非已经证明的缺陷；本版平板实际单击和双击尚不存在。此前OPPO新App单点、双点、上下滑已获用户反馈通过。

## 路线与边界

保留原蓝牙HID键盘Report ID 1及方向键含义，在同一GATT服务中新增Report ID 2实验性**标准HID绝对坐标输入**：向系统报告屏幕中心坐标及接触/释放；一笔短触最多产生一次按下/释放，两笔快速短触产生两组按下/释放。优先验证数字化笔/触控类别的标准报告，不冒充具体厂商或沿用第三方设备的VID/PID；具体描述符和释放序列先在主机测试和现有SDK中核对。坐标取报告范围中点，不读取屏幕内容或注入额外命令。

这是一条**待实测**路线。HarmonyOS对该BLE输入类别的识别、中心映射、前台抖音接收和双击效果未知；连接和通知成功不代表屏幕实际点击。若系统不识别、点击位置错误或视频App不响应，记录现象并停下分析，不自动切到普通鼠标、自动点赞、鸿蒙App或要求删除配对。[USB HID Usage Tables](https://www.usb.org/sites/default/files/hut1_3_0.pdf)定义数字化输入用途；[ESP32 BLE Mouse Gateway](https://github.com/folgercn/ESP32-BLE-Mouse)有通过BLE报告绝对数字化笔坐标的实现，但其Android用途不能证明MatePad兼容，也不引入它的Wi-Fi和自动化。

不改变OPPO原App协议和手势；平板按真实轻点发送，现有触摸异常/切换/断线时取消未发动作并在可行时发送本连接中性释放。设备不可用时不跨连接补发、不自动执行；上下滑仍发送原箭头。点击报告与键盘报告分别跟踪本连接、加密、绑定、身份、订阅、路由和代数，最终发送前再校验；App意图获锁后立即禁止平板非中性动作。每次真实触摸只走一条路由。

双点不得因HID现有500ms冷却丢失：新点击报告完成释放后立即可处理下一笔；执行中短时保留至多一笔新点击并严格设置过期，不能无限积压，停止或断开清除。为符合即时操作目标，dual键盘方向动作也去掉额外500ms冷却，但保留按下后可靠释放、冲突时不重放历史；保持独立`hid_probe`旧源码和恢复入口。手动测试仍不变。具体间隔在报告状态机与真机验证中确定，不保证零延迟。

## 服务表、保留与恢复

**实施中修正（2026-10-27）：** 固件2eb2和诊断版aa895在实板启动时确认：SDK的`BLEService::addCharacteristic`在NimBLE下对同一服务内重复UUID去重，导致第二个0x2A4D没有注册，pen句柄65535；原App/键盘句柄正常。按[HID over GATT规范的多HID服务实例](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/hogp_v1-2_1777405843/HOGP_v1.2/out/en/index-en.html)改为一个BLE服务器内的两个HID服务：原键盘服务原样保留，第二HID服务只承载数字笔报告及独立描述符。保持用户操作、路由、绑定和输入范围不变，不改SDK、不新增依赖；真实主机是否枚举第二服务仍待实测。当前SDK按UUID查服务会返回第一个，必须保留两个对象的特征指针并按实际值句柄区分，不以UUID查询第二服务。

新增输入特征及报告描述符会改变GATT/HID表；保留已登记OPPO身份、原bond、已有广播和App UUID/报文。注册多个报告和启动整个GATT表的顺序按现有SDK接口核对，不复制一套BLE服务端；对新旧输入独立检查订阅和句柄。继续发送Service Changed，但旧绑定设备是否刷新缓存必须实测。[Bluetooth GATT规范](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core-54/out/en/host/generic-attribute-profile--gatt-.html)说明已绑定客户端可能跨连接缓存服务表；不能保证全部机型刷新。

不删除系统配对、不清除NVS、不整片擦除、不自动确认配对；发现缓存阻塞则保留现状、报告再决定。现有`8dceb`构建清单和独立touch恢复材料保留；实施前校验完整产物哈希和恢复入口，出现问题不强制恢复或删除任何绑定。用户自行操作连接/配对。

## 验收

1. 电脑端先测描述符、坐标/按下释放字节、短点路由、快速两次、队列过期、路由/会话失效、中性释放和双报告订阅；旧键盘/App以及构建清单回归通过，再完整编译。
2. 更新前重核唯一CH343/ESP32-C3、恢复产物和烧录目标；不更换手机App、不改接线。若硬件不在线，先完成电脑端验证。
3. 用户在MatePad连接设备并保持视频页，分别测试单击、快速双击、上下滑；记录是否出现鼠标指针、点击位置/效果及实际失败。双击在部分视频App可能点赞。再在OPPO验证App连接及原单点、双点、上下滑，以及切换回平板；未实际完成不记通过。
4. 若单击无效，不推断是触摸芯片或配对失败；结合板端真实报告、订阅状态和用户画面定位。无论结果如何保留现有绑定及原8dceb产物。

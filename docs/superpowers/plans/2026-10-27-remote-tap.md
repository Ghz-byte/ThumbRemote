# 手机遥控单击与快速响应实施计划

> 执行：本会话内逐项实现与验证；用户已确认中心单击、快速两次单击及取消固定冷却。

**目标：** OPPO App 遥控中，触摸板短点在松开时立即发出屏幕中心单击；两次快速短点产生两次按序点击；上下滑没有额外500ms冷却。

**架构：** dual目标在保留原手势识别器的基础上识别短点，App事件码5表示单击，原方向码不变。Android保持单手势执行，繁忙时有限缓冲新动作，前一个完成后立即执行未过期动作；首个单击不等待双击判定。单独touch/hid目标保持原字节源码。

**约束：** 触摸释放才产生动作；断线、锁屏、停止、路由变化、触摸异常不补发；一次控制一台；已绑定身份保留；仅OPPO App支持新点击，MatePad HID行为不变；不新增权限、不删文件、不提交。用户处理系统授权。真实短触阈值和目标App反应需实测。

## 工作项

- [x] 修改dual触摸协调及测试：短触识别、长接触不触发、抖动和移动路径判定，断线或异常后等待完整释放，HID不发点击；验证上下滑保持原行为。
- [x] 修改dual传输及测试：码5编码与现有协议兼容；发送侧采用最多4条、100ms有效期的短队列，READY仍优先、状态失效不发送。原单槽在两次到达而host未取走时丢第二次，回归先失败4项，故改队列。
- [x] 修改Android协议、遥控队列及测试：验证码5、无冷却、首次立即执行、忙时最多短暂有界排队并按序执行；过期、停止和旧会话回调不执行。
- [x] 修改Android执行适配：遥控允许中心单击，遥控即时执行不受手动操作冷却限制；同一时刻只有一个手势，完成或拒绝后处理下一个，保持手动模式原样。
- [x] 运行`scripts/esp32.ps1 verify -Target dual`与`scripts/android.ps1 verify`并检查产物；保留历史产物，不清绑定。
- [ ] 重核唯一板卡和唯一已授权手机后，按现有构建入口更新；记录版本、日志，邀请用户实测单击、快速双击、上下滑和切换。未实测项目标记未验证。已更新并观察启动状态，待用户实测。

## 重点检查

- 第一个单击不能因等待第二下而延迟；第二下若在第一个80ms点击期间到达，应在前者完成后立即执行。
- 滑动过程中输入不能中断前一手势；有限队列溢出、过期及执行失败要明确记录，不积压旧动作。
- 更新后旧独立固件、配对信息和MatePad箭头行为不变；不以电脑测试冒充真机结论。
- Android BLE回调顺序、同会话sequence、停止和重连时旧回调必须继续过滤。

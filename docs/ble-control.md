## 使用方式

1. 保持现有四线和开发板USB供电、手机蓝牙开启。不需要重新焊接或烧录。
2. 打开ThumbRemote，在“蓝牙接收测试”点扫描并选开发板；此模式仍只记录方向。
3. 亲自开启辅助功能服务。回到App点“开始遥控”；首次通知授权由用户亲自允许，授权后再主动点一次开始，权限回调不自动开启。
4. 允许通知及“遥控运行状态”通道显示。服务重新连接开发板并新握手，看到“遥控已开启，可切换到目标应用”后自行切换抖音。
5. 硬件上滑/下滑并松手，分别触发手机上滑/下滑。左右只记录，不执行。两次操作间留约1秒；忙/冷却/过期的事件直接丢弃，不排队。
6. App内或通知栏可“停止遥控”；锁屏/熄屏、断线、关蓝牙、附近设备/通知不可用、辅助功能中断/断开、任务移除均结束。恢复条件后不会自动重新连接或恢复会话，须回App主动开启。

遥控作用于当前正在使用的应用，不识别抖音或视频内容。系统报告完成只代表手势派发结果，实际视频是否切换需用户确认。停止不能保证撤回系统已经接收的一笔滑动，但会禁止后续输入并使迟到结果失效。

## 实现关键点

- RemoteControlService是唯一BLE至辅助功能协调层，connectedDevice前台服务持有独立BleClient；页面只绑定/显示，不持有服务Gatt。原接收页面离开仍断开自己的连接。
- 接收测试旧Gatt先断开，服务使用新的sessionId重新订阅/握手。BleClient只回调协议校验新接受的帧，不回放记录列表。通知回调在排入主线程前捕获单调接收时间，至执行超过500ms丢弃。
- RemoteControlSession维护运行代数/请求id、上下方向、重复和30条内存结果；500ms完成冷却、单任务互斥。RemoteControlStatus维护启动票号，避免重复点击和旧启动Intent在停止后复活。
- 辅助功能原5秒手动路径保持，新增即时入口共享GestureSession、几何与系统派发。遥控启动/运行期间禁用手动发起；有手动任务时拒绝启动遥控。
- 新增FOREGROUND_SERVICE/FOREGROUND_SERVICE_CONNECTED_DEVICE/POST_NOTIFICATIONS。通知可见是产品启动条件，不宣称POST_NOTIFICATIONS是Android启动前台服务的必要条件。无新增网络/定位/窗口读取能力、数据库或持久化日志。
- 服务START_NOT_STICKY，无开机恢复、自动重连、历史补发或唤醒锁。不承诺OPPO长期后台存活。协议sessionId不具备设备认证能力，本轮无新绑定协议。

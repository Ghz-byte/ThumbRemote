## 软件手势识别 v2（2026-10-25）

用户已同意修改并重新烧录。v1 的原始触摸输出保留；v2 额外在松手后输出 `GESTURE direction=UP/DOWN/LEFT/RIGHT dx=... dy=...` 或 `GESTURE_REJECT reason=...`，不发送蓝牙消息。

- 以起点和最后有效坐标的净位移判断；主轴至少40原始单位，主轴至少为次轴2倍（等号接受）。这是初始软件参数，不是硬件精度或体验已验证的结论。
- 原始 X减/增→上/下，Y减/增→右/左；仅适用于上一轮实测朝向。屏幕旋转后需要重新对应，本版无自动方向感知。
- 一次接触只在查询00或有效坐标mask0时结束并判定一次；01保持当前接触，静止、轻点和往返归零不触发方向。
- 上电/重启先等确认松手，避免从半次接触的中途起点开始。01但没有已知起点时也等松手。
- 通信错误或短读取消本次接触；即使数据恢复，也必须完全松手才可重新开始。多点或点号切换同样取消。取消会在已知松手后输出拒绝，不补发方向。
- 正常非坐标报告（包括芯片自己的Flick包）仍只作诊断并忽略，不触发松手或软件方向，不因它们取消所有正常滑动。
- `STATUS` 新增 `gestures` / `rejected` 累计数；`rejected` 包含轻点/短距离等预期过滤，不等于通信错误。

主机用 `gesture_recognizer_test.cpp` 测状态/阈值/故障恢复，并用12组原始实测起止坐标验证四方向；不把这些回放当作 v2 上板准确率。最终编译、上传和手势实测状态以 WORK_LOG 为准。

电脑端167项检查与完整编译通过，程序308584字节、RAM14260字节，已上传。最终产物及日志目录为 `%TEMP%/thumbremote-touch-ac895c144276/`。

v2实物测试已取得四方向各3条正确事件（其中两个窗口首笔起点在窗口外，不能称12笔完整接触），6次完整轻点全部too_short拒绝，另行3次完整斜滑全部ambiguous拒绝；观察到的方向事件都紧跟raw UP，通信错误累计0。多点和实物通信故障恢复、长期准确率未验证。日志名/位移/窗口边界见 WORK_LOG 最新v2节。

|---|---|---|

GPIO4/5 是本次固件显式选择，不是 Wire 的默认接线。板上 +5V 不用于触摸供电。所有插拔保持断电，使用 USB 给开发板供电，不接面包板电源、电池或显示 SPI。用户已检查排针无漏焊、反馈接头无偏移，助手未做万用表短路检查；后续用户表示“还没插这些东西”，因此四线实际是否已接及 USB 状态须以其最新反馈为准，不标为已完成。

## 程序如何工作

- Arduino Wire：100 kHz，50 ms 事务超时，20 ms 轮询。只探测文档默认 7 位地址 0x46，不遍历或写其他设备。
- 先写查询选择字节 0x80，STOP 后读 1 字节；新包 bit7=1 时选择 0xE0，读 14 字节。STOP 分隔形式依据编程指南第 10 页。
- 只把格式高四位为 0 的报告作为坐标，完整组合三个点的 12 位 X/Y；不假定坐标范围就是 0–239，不旋转、不映射。
- 查询高两位 01 为仍按着但无新包，不报松手。00 明确无触摸，可结束已有接触；坐标包有效点 mask=0 也可结束接触。NAK、短读或未知报告不触发 UP。
- DOWN/MOVE 输出点号、坐标、有效位，UP 输出判定来源；静止时可能不连续输出坐标，每 2 秒仍有 STATUS 心跳。
- 无主动 RST/INT 接线，无触摸配置命令或升级，无 BLE、显示、Android 改动。
- ACK 只说明地址应答；连续坐标、移动方向、松手和长期稳定性均须分别实测。

## 验证命令

```powershell
powershell -ExecutionPolicy Bypass -File scripts/esp32.ps1 test
powershell -ExecutionPolicy Bypass -File scripts/esp32.ps1 verify
powershell -ExecutionPolicy Bypass -File scripts/esp32.ps1 upload -Port COM7
```

test 使用现有主机 g++，不安装依赖。verify 将 sketch 按 SHA-256 镜像至 `%TEMP%/thumbremote-touch-<hash>/touch_probe/`，完整调用既有官方工具链，DIO/80 MHz/4 MB；manifest 绑定源哈希、FQBN、构建目录所有 bin 及平台实际上传使用的 boot_app0.bin 的 SHA-256。upload 拒绝未构建、源变化、产物变化或端口歧义，先确认唯一 CH343 与 ROM 芯片身份后写入，不整片擦除。不自动串口读取，读取时用 115200/8N1 并在结束释放端口。

## 上板验收

1. 确认四线连接与供电；插入开发板 USB，仅连接这一块目标板。
2. 核对端口，执行已授权的上传，检查退出码与写入校验。
3. 115200 串口观察启动、ACK 和 STATUS；未应答时先记录原始错误。
4. 用户依次按下、缓慢移动、松开；实际取得 DOWN/MOVE/UP 才分别记为通过。明确区分串口程序运行、地址应答与连续触摸成功。
